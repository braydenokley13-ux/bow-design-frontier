# Verification open, authority operated

*Hybrid Advocate, facts dated 2026-09-29. Speculation is marked; thresholds are my proposals, not findings.*

## Thesis

Open the layers a stranger needs in order to **check** a BOW record. Operate, and keep closed, the layers that carry **authority, history and licensed content**.

The clone test says closing code protects almost nothing: four engines were rebuilt from screenshots in 12–22 calls. It also says what a copy could not be: the canonical World, the sourced rulebook, the accumulated record. So the boundary defends no code. It sits where *checking* ends and *authority* begins.

**Decision rule, per layer.** Open the **source** if (1) openness makes BOW's own claims more credible and (2) a third party reselling that layer would not consume BOW revenue. Open the **spec** if (1) holds and an independent second implementer is plausible within about 24 months. Otherwise close it, or mark it "not yet" with a trigger.

Test (2) is what Elastic (2021), HashiCorp (2023) and Redis (2024) failed: each opened the thing it sold, watched hyperscalers sell it, relicensed, and got forks (OpenSearch, OpenTofu, Valkey); Elastic and Redis later added AGPL. BOW sells authority and persistence, never the format.

Two guardrails. Inspectable is not licensed: "How do we know?" is free inside every product, whether or not a rulebook is licensed for reuse. An open format is not open data: no student record enters a public address space.

## Per-layer call

| Layer | Call | Reason and exact line |
|---|---|---|
| L0 Record | **Open spec + open source** (Apache-2.0, patent grant) | Decision Receipt v1 already verifies in a second browser; a district cannot trust a receipt only the vendor can verify. Includes one canonicalisation and hash (the repo has three non-identical canonical-JSON functions), typed unknowns, statuses. |
| L1 Address | **Open spec** | Minted without permission, names its frame (semantics version), content-derived so it survives our registry. The name-to-head *registry* is operated. |
| L2 Contract | **Open spec + reference fold/verifier + conformance vectors.** Rulebook *language*: **not yet.** Rulebooks: closed content, inspectable | A determinism contract is checkable. A language before three independent rulebooks exist is VRML97. |
| L3 Host | **Closed, operated.** Reference host: not yet | Seats, time authority, identity and leases carry child-data safety and revenue. Closing buys little against copying; the reasons are test (2), safety, and option value (closed-to-open later is possible, the reverse is not). |
| L4 Representation | First-party Browser and packs closed; record viewer open (inside the verifier). **Projection contract: not yet** | The seat auditor guards displayed facts, not derived secrets; a confidentiality promise we cannot keep is worse than none. |
| L5 Network | **Not yet.** `bow-bridge-1` published as an informational draft | Standardise after two independent hosts transact. |
| L6 Connectors | **Closed, licensed.** Only a licence-in-provenance field is in L0 | Licences are the asset; open layers carry no league data or likeness. Writeback: not yet. |
| L7 Intelligence | **No new spec.** An agent is a seat: it gets a seat's projection and emits acts. Thin adapters open | Interchangeability comes from seat semantics. |
| L8–L9 | Authoring kit open when stable; **marketplace and non-education verticals not yet** | Both need external authors first. |

## Triggers, and the reverse direction

Sequence: Experimental drafts now, then T1 to T6 in roughly that order, each moving only on evidence.

| Move | Trigger |
|---|---|
| **T1** Draft to Stable v1 (compatibility promise) | One real class on each product; the spec-only clone (below) passes; one non-BOW author has shipped against it. |
| **T2** Neutral governance for L0–L2 | Two conformant implementations with no BOW funding; or two prospective implementers name BOW's sole-editor role as the blocker; or a buyer requires it. Target a Joint Development Foundation-style home (OpenUSD's route); BOW keeps an editor seat and a "BOW Verified" mark. |
| **T3** Open a reference host | Procurement demands self-hosting, or three external Worlds need shared authority we will not host free. License **AGPL-3.0 from day one** (accepting enterprise friction), single tenant; control plane, registry and identity stay closed. Never open-then-restrict. |
| **T4** Rulebook language | Three independently authored rulebooks in two domains share constructs and an outsider asks. Derive it; do not design it. |
| **T5** L5 spec | Two independent hosts complete a cross-World transaction. |
| **T6** Marketplace | About ten external Worlds published unaided, one creator paying for hosting (speculative). |

**Narrowing triggers**, the only moves toward closed: a rival registry or false "compatible" claims (answer: trademark and certification, never relicensing); a published projection rule leaks (withdraw the confidentiality *claim*, keep the spec); a student-privacy incident or COPPA change (cut public routes to records that could hold student data). Rights on a shipped version are irrevocable; an open layer never becomes source-available. Publish this as a **Layer Charter** first.

## What compounds, and how the boundary holds

*Open side compounds:* verifiable records, implementers, agent-legible tooling, buyers' exit rights. *Closed side compounds:* World One's unbroken record, signed heads in a public log, dated rulebooks right on both sides of every trade, child-safety operations, licences.

**Against commoditization:** a rival with the whole open stack has a viewer and a toy World, not the history everyone cites, the keys, the rulebooks or the licences. Honest caveat: today all of that is near zero (history starts at first start; authority is a borrowed host ACL). The real risk is delay in operating the canonical instance.

**Against starvation:** a *sufficiency test*: a stranger can do one useful thing without asking us. Verify a receipt; embed a Moment (the lockstep fold runs in any browser, so single-player Moments need no host); author and export records. Plus: no paid fields in the spec; every hosted record exports for offline verification; the free door stays free.

## The required topics

- **Adoption:** the product carries adoption; the spec is an option, arriving if at all via verification links and embeds. Speculation: coding agents that read a spec cut third-party tooling costs.
- **Monetization** (no price list): persistence, hosting, licensed data, district and enterprise licences with receipts, later marketplace take.
- **Developer ecosystem and moat:** spec, verifier, fold library, vectors, later an authoring kit; the first implementers are our own two products. The moat is instance, history, rulebooks, keys, trust operations, licences, not code.
- **Security and trust:** publishing formats and hashing is safe (Kerckhoffs); the attack surface is the host and projections, both closed. Head authority today is a platform ACL and comparison is 32-bit; a full 64-hex signed head, also posted to a third-party log, must precede any "verifiable" claim. Then an operator cannot silently rewrite World One.
- **Network effects:** zero today. Plausible: verification (the more places can check a record, the more it is worth as evidence, as with PDF readers) and, much later, cross-World contracts.

## Analogies, and what each teaches

- **Android/AOSP vs GMS:** Apache code; the moat was Google's services plus a compatibility definition and test suite (our L0–L2 plus "BOW Verified"). Cautions: the EU's 2018 fine over tying, and Google's March 2025 move to private AOSP development.
- **Git vs GitHub:** open protocol, clone-to-leave; hosting and the social layer captured the value. **PDF:** published 1993, ISO 32000-1 in 2008; free reader, paid authoring, governance after adoption. We have no adoption yet.
- **OpenUSD vs Omniverse:** Pixar opened code in 2016, the Alliance formed August 2023, Core Specification 1.0 landed December 2025: code first, governance late, a proprietary platform on top.
- **Chromium vs Chrome; VS Code vs Marketplace:** open engine, closed distribution. Warning: one vendor steers the "open" thing (Microsoft cut its C/C++ extension off from Cursor and other forks, April 2025). LSP shows such a spec can still win.
- **Unity, Stripe, Figma:** Unity's Runtime Fee (2023, cancelled September 2024) shows retroactive terms burn trust. Stripe documents its API and keeps network and risk data (my reading). Figma won with a closed multiplayer runtime plus documented APIs, not an open format.

## Failure modes of my own strategy

1. **Wrong boundary.** If verifiers or rulebooks are the value, commoditization takes it. Canary: do outsiders ask for our hosting or our record?
2. **Sole-editor capture** (OOXML, Chromium). Mitigation: T2, public vectors, patent non-assert.
3. **Relicensing chill.** Even a rumor deters adopters. Mitigation: the Charter.
4. **Fragmentation.** Doom demos desync across engine versions; our repo has at least five `bow://` grammars. Answer: vectors, and a declared frame in every address.
5. **Attention tax and a frozen wrong spec.** Label everything Experimental; promise nothing before T1.

## Next 12 months, given today's facts

1. **Months 0–2:** one canonical serialization and hash; L0 and L1 drafts written *from* Receipt v1 and X3Proof; one address grammar; publish the Charter and Experimental drafts with tamper-case vectors. The first job is unifying our own two products.
2. **Months 1–4:** run World One on a real shared store with a full signed head, anchored externally. The closed moat's clock starts here.
3. **Months 3–6:** the **spec-only clone test**: an unrelated model, given only the spec and vectors, must build a verifier that matches every vector and rejects every tamper. Failure means the spec omits what screenshots hide. Then publish our verifier.
4. **Months 4–9:** first real classes on both products; first both-sides sourced rulebook; student data only in the closed store.
5. **Months 6–12:** one non-BOW author ships a small World or embed unaided. Publish a quarterly ledger of which triggers moved.
6. **Do not build** a marketplace, federation spec, rulebook language, foundation, or self-host release.

## Strongest objection, and my answer

*"A hybrid is not choosing. With zero users and no outside developers, openness is cost without benefit, and closure forecloses the standard. Your boundary is unfalsifiable."*

The costs are asymmetric. An Experimental spec and a small verifier cost documentation and test vectors BOW needs anyway: its record must outlive its tools. Closing L0–L2 would give away the credibility feature ("another browser verifies it") for protection the clone test shows we do not get. Going fully open would put L3 and licensed data on the wrong side of test (2). The boundary is falsifiable: T1, T2, the spec-only clone test and the ledger say when it is wrong. If no outsider ever implements L0, we lost a few weeks and kept a verifier our own products needed.
